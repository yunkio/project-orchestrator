# 체크리스트로 계속 확인하기

시작·재개 때 읽고 모든 단계에 적용한다. [CHECKLIST 양식](../assets/CHECKLIST.md)을 사용자의 기록 경로에 별도 문서로 둔다. 양식을 복사했다는 사실은 확인 완료가 아니다. 질문·의도·명세·작업 원장은 기존 문서에 유지하고, 체크리스트는 그 근거를 연결해 빠진 절차와 요구를 찾는 데 쓴다.

## 만들고 유지하기

1. 기록 경로가 정해지기 전에는 기존 QnA 절차대로 임시 QNA만 만든다. 경로가 정해지면 새 실행은 초기화 도구 또는 양식으로 CHECKLIST를 함께 만든다. 기존 실행에 CHECKLIST만 없으면 기존 기록·현재 변경을 읽고 이 문서만 보완한다. 전체 초기화나 완료 상태 재설정은 하지 않는다.
2. 기본 G0~G6 항목을 유지하고, 프로젝트 지침·원자료·사용자/현업 답변의 실제 조건을 **지시 항목(C-I)**과 **요구 항목(C-R)**에 연결한다. 요구의 상세 원문·통과 조건·구현/검증 추적은 REQUIREMENTS에, 실행 기록은 WORKLOG에 두고 ID와 위치로 참조한다. 여러 조건이 섞인 요구는 먼저 REQUIREMENTS에서 판정 가능한 조건으로 나눈다.
3. 모든 필수 요구에 연결 행이 있는지 REQUIREMENTS→CHECKLIST 방향으로 대조한다. 반대로 각 행에 실제 출처가 있는지도 확인한다. 새 요구나 현업 답변이 생기면 이 연결을 갱신한다. 체크리스트에 안 적혔다는 이유로 원문의 요구가 사라지지는 않는다.
4. 메인이 CHECKLIST를 편집한다. 배정 계약에는 관련 항목 ID·기준 버전·확인 방법을 전달한다. 하위 에이전트는 고유 보고서에 항목별 결과·근거·미확인을 반환하고 메인이 실제 파일·실행을 확인해 반영한다.

## 상태와 근거

상태는 **대기 / 진행 / 답변 대기 / 확인 완료 / 재검토 / 미완료 / 적용 없음**이다. 상태 이름만 채우지 말고 근거 위치와 그 근거가 적용되는 의도·명세·코드·입력 버전을 남긴다.

- `확인 완료`: 해당 조건을 실제 확인한 최신 근거가 있다. 계획·파일 존재·에이전트 반환만으로 실행 검증이나 독립 검토를 완료시키지 않는다.
- `답변 대기`: QNA ID와 그 답에 의존하는 작업을 연결한다. 독립 작업까지 정지시키지 않는다.
- `적용 없음`: 실제 원문·명시된 요청 범위에 따른 이유가 있다. 예를 들어 계획까지만 요청한 실행의 제품 구현은 범위 밖으로 표시하되, 제품 전체 완료를 주장하지 않는다. 필수 요구의 미구현, 시간·도구 부족, 실행 불가능한 독립 검토는 적용 없음이 아니다.
- `재검토`: 의미 있는 답변·원자료·명세·코드·입력 변경으로 종전 근거를 현재 통과 근거로 사용할 수 없다. 이전 근거는 보존하고 변경 이유와 다시 확인할 일을 남긴다.

현재 요청 범위 안에서 **그 단계에 필요한 확인 수준**으로 항목과 선행 조건을 확인한 뒤 WORKLOG의 단계를 통과시킨다. G1은 요구 추출·의도 확인, G2는 명세·검사·배정 준비, G3은 실제 구현·통합, G4~G5는 실행·독립 검증, G6은 설명·인계를 판정한다. 이후 단계에서 충족할 요구가 아직 최종 완료되지 않았다는 이유로 준비된 G2나 해당 구현 작업을 막지 않는다. **C-R의 최종 확인 완료는 그 요구의 실제 통과 근거가 있을 때만 표시**하고, G2 명세 반영 같은 중간 확인은 별도 칸에 기록한다.

현재 작업의 중요한 미확정 답·독립 지적·선행 조건 미충족이 있으면 해당 작업은 보류한다. 통과한 작업에 새 영향이 없다면 검사를 형식적으로 반복하지 않는다. 작업 보고와 CHECKLIST·REQUIREMENTS·WORKLOG의 상태가 다르면 실제 근거를 대조해 바로잡는다.

## 언제 다시 보는가

| 시점 | 확인할 범위와 다음 행동 |
|---|---|
| 시작·재개 | 현재 단계·열린 항목·최신 QNA/의도/명세·실제 변경을 대조하고 다음 행동 결정 |
| 단계 진입·종료 | 해당 G 항목과 연결 지시·요구, 선행 조건·미해결·확인 근거를 확인 |
| 위임 전 | 관련 항목·계약·수정 소유권·입력 버전과 검토자의 실제 독립성을 확인 |
| 주요 쓰기·반환·통합 | 기준 변경 여부와 반환 근거·통합 동작 확인. 에이전트 반환을 완료로 직결하지 않음 |
| 사용자 답변·원자료·명세 변경 | 요구→결정→계획→작업→검사→설명에 연결된 항목만 재검토. 최신 세대와 범위를 에이전트에 전달 |
| 결함 수정 | 동일 실패와 영향받는 정상 검사·설명까지 재확인하고 근거 버전 갱신 |
| 최종 전달 전 | 현재 요청 범위의 모든 단계·필수 요구·지시·독립 지적과 미완료를 전체 대조하고 인계 상태에 반영 |

매 도구 호출마다 전 항목을 다시 쓰지 않는다. 각 시점에 관련 항목만 확인하고 **최근 확인 이력**에 시점·계기·항목 ID·기준 버전·판정/다음 행동을 한 행으로 남긴다. 같은 근거를 여러 문서에 복사하지 않는다. 중요한 미완료·선택은 사용자에게 설명하며, 체크리스트 갱신을 사용자 동의로 해석하지 않는다.

## 독립 검토를 오염시키지 않는다

채운 CHECKLIST에는 부모의 해석과 기대가 들어 있다. **G2/G5 원문 감사의 1차와 G6 그래프 첫 읽기에는 제공하지 않는다.** [원문 감사](requirements-and-audit.md)·[그래프 검토](graph-handoff.md)의 입력 순서대로 첫 보고를 보존한 뒤 2차에 CHECKLIST와 현재 원장을 공개한다.

2차 검토자는 독립 도출 목록과 실제 요구·산출물·체크 상태를 대조한다. 근거 없이 완료 처리한 항목, 빠진 요구 연결, 오래된 증거, 허위 적용 없음을 지적한다. 메인은 수정·근거 있는 기각·미해결을 처리하고 영향받은 항목만 다시 확인한다. 체크리스트 자체의 정합성 검토가 제품 실행 검증이나 사용자의 이해 확인을 대신하지 않는다.
