# 에이전트 배정과 재개

G2의 작업 분해, G3~G4의 병렬 구현·검증, G5의 독립 감사, G6의 그래프 검토, 모든 재개 때 적용한다. 메인이 통합·판정 책임을 지며 QNA, USER_INTENT, REQUIREMENTS, SPEC, WORKLOG, CHECKLIST, HANDOFF 원장은 메인만 편집한다. 하위 에이전트는 계약에 지정된 코드 또는 고유 보고서만 수정한다. 위임·반환·통합 때 [체크리스트](checklist-and-gates.md)의 관련 항목과 최신 기준을 확인한다.

## 단계별 역할과 독립성

메인은 실제 도구·시간·의존성에 맞춰 아래 역할을 배정한다. 역할마다 에이전트를 무조건 늘리지는 않는다. 일반 조사·구현 역할은 소유권과 기준이 유지되면 재사용할 수 있지만 새 맥락이 필요한 검토를 맡기기 위해 이력을 지웠다고 주장하지 않는다.

| 단계·역할 | 입력과 수행 | 독립성·반환 기준 |
|---|---|---|
| G0~G1 조사·현업 분석 | 확정된 범위의 자료 조사·질문안·검증 기준을 병행 | 직접 읽은 출처·미독·가정 반환. 질문·최종 요구 통합은 메인 담당 |
| G2 요구 감사 | 원문·당시 질문/답변 문맥 → 1차 보고 보존 → 명세·계획 대조 | 새 맥락 필수. 부모 해석·채운 체크리스트는 1차에 제외 |
| G3 구현 | SPEC·입출력 계약·소유 경로·관련 체크 ID | 독립 모듈을 병렬 구현하고 실제 검사·미확인 반환 |
| G4 검증 | 원자료·명세에서 기대 결과 도출, 실패·품질 검사 | 해당 구현의 작성자가 아니어야 함. 메인이 핵심 코드를 작성했다면 다른 에이전트가 검사. 새 맥락 사용 여부를 구분하고 작성자 결론만으로 통과시키지 않음 |
| G5 최종 감사 | 원자료에서 요구를 새로 도출한 뒤 최신 통합 결과 대조 | G2·구현 이력을 상속하지 않는 새 맥락으로 다시 시작 |
| G6 그래프 독자·사실 대조 | 그림·인접 설명 먼저 읽기 → 첫 보고 보존 → 실제 자료 대조 | 그림 작성에 참여하지 않은 새 맥락. 사실 대조 뒤 의미·경로 설명을 수정하면 해당 범위는 새 독자가 다시 읽음 |

독립성이 필요한 역할은 준비된 명세·코드 전체를 먼저 노출한 뒤 독립으로 바꿔 부르지 않는다. 필수 검토 기능이 없으면 아래 제약 처리와 미완료 판정을 따른다.

## 가용성·자원 확인

- 현재 제공되는 하위 에이전트 도구, 허용 범위, 실제 동시 실행 여유, 시간·자원 한도를 확인한다. 특정 도구명·슬롯 수·모델 버전·예산을 가정하지 않는다. 알려지지 않은 한도는 모름으로 기록한다.
- 이 절차는 사용자가 요청한 병렬 위임을 실제로 수행한다. 독립된 작업이 둘 이상이고 실행 여유가 있으면 병렬로 배정한다. 역할 이름만 적거나 모두 순차 처리한 것을 병렬 수행이라고 보고하지 않는다. 의존성이 있거나 여유가 없으면 이유와 실제 순서를 남긴다.
- 가용 도구가 지원하는 새 맥락 생성 옵션을 사용한다. `spawn_agent`가 제공되면 독립 감사에는 `fork_turns="none"`을 지정한다. 동등한 분리 기능이 없는 에이전트는 독립 감사자로 부르지 않는다.
- 기능 자체가 없거나 허용되지 않으면 그 제약과 영향을 기록한다. 새 사용자 채팅이나 외부 에이전트 호출로 분리를 가장하지 않는다. 메인의 대체 자체 점검은 **비독립·불완전 대체**로 표시하고, G2의 독립 대조/G5 독립 검토는 통과시키지 않는다. 가능한 허용 작업과 인수인계 준비를 수행하되 전체 완료로 포장하지 않는다.
- 구현, 통합, 검증, 독립 감사, 인수인계 준비에 필요한 시간을 함께 배분한다. 진행 중 남은 시간을 갱신하고 선택 기능부터 줄인다. 자원 부족은 필수 검증을 실행했다고 적을 이유가 아니다. 사용자 선택이 필요한 범위·품질 절충은 QNA에 둔다.
- 고정된 종료 시각이나 전체 제한 시간이 있으면 QNA 답변 대기와 에이전트 대기도 경과 시간에 포함한다. 대기 중 타이머가 멈추거나 마감이 늘어난다고 가정하지 않는다. 질문을 줄이고 독립 작업을 병행하되, 시간이 흘렀다는 이유로 사용자 답을 대신 선택하지 않는다.

## 배정 계약

작업마다 WORKLOG에 다음 계약을 남기고 해당 에이전트에 전달한다. 독립 작업은 고유 ID·출력 경로를 가진다.

| 항목 | 필수 내용 |
|---|---|
| 목적 | 작업 결과, 연결 요구 ID·의도 ID·체크 ID, 작업 세대/의도 버전 |
| 입력 | 원자료·입력 버전, 현재 존재하는 의도·명세·계획과 선행 작업. 제품 구현은 SPEC 버전·연결 절·계획 작업 ID·인터페이스가 필수 |
| 소유권 | 수정 가능한 정확한 경로, 읽기 전용 범위, 금지된 공유 원장 |
| 완료 조건 | 입출력 계약, 실제 확인 방법, 필요한 근거, 남겨야 할 한계 |
| 자원·중단 | 시간/자원 범위, 의존 답변, 취소·버전 변경 시 행동 |
| 반환 | 읽은 의도 버전, 변경 파일, 관련 체크 ID별 실행 명령/동작·입력·관측 결과, 결함·가정·미검증·다음 의존성 |

일반 에이전트는 시작할 때 현재 존재하는 USER_INTENT, 연결 요구, 해당 SPEC 명세·계획을 직접 읽고 버전을 반환한다. **G0~G1 조사는 원자료·확인된 질문/답변 문맥과 현재 존재하는 의도로 시작하며, 미작성 의도·SPEC·계획은 미작성으로 표시한다. 아직 없는 문서를 만들거나 그 작성을 기다리기 위해 조사를 막지 않는다. 제품 구현 배정부터 해당 SPEC·계획을 필수로 한다.** 주요 쓰기와 반환 전에도 배정 세대와 최신 의도가 유효한지 확인한다. 중요한 해석 차이는 메인에게 보고하며 직접 QNA 답변을 만들거나 범위를 바꾸지 않는다.

**원문 감사 1차의 별도 입력 순서:** 부모의 USER_INTENT 해석을 먼저 읽지 않는다. 의도 버전 ID와 답변 당시 질문 ID·버전·조건·선택지 원문 및 사용자 답변·직접 밝힌 이유로 시작한다. [원문 감사의 1차 봉인](requirements-and-audit.md)을 마친 뒤 2차에서 USER_INTENT와 CHECKLIST를 읽는다. 감사 1차에 부모의 누락 예상·요구표·채운 체크리스트·결론을 주지 않는다.

**G6 그래프 읽기 검토도 별도 입력 순서를 따른다:** [그래프 절차](graph-handoff.md)의 그림과 인접 범례·표·요약을 먼저 읽고 해석을 저장한 뒤 원문·SPEC·코드·근거와 대조한다. 이 두 예외를 일반 구현 에이전트의 의도 확인 생략에 적용하지 않는다.

## 작업 그래프와 통합

- **실행 흐름**은 제품에서 요청→계산→진행 상태→검증→저장/조회가 어떻게 동작하는지를 나타낸다. **작업 DAG**는 누가 어떤 산출물을 만들어야 다음 작업이 가능한지를 나타낸다. SPEC 계획과 WORKLOG의 실제 상태를 같은 작업 ID로 연결한다. 최종 HANDOFF의 그래프 구체성과 검증은 [그래프 절차](graph-handoff.md)를 따른다.
- 각 작업에 선행 ID, 소유자, 수정 경로, 상태, 완료 근거를 둔다. 같은 파일을 동시에 수정하게 하지 않는다. 공통 계약을 먼저 정하고 독립 모듈·조사·검증 설계를 병행한다.
- 반환은 완료가 아니다. 메인이 실제 변경, 요구 충족, 실행 근거, 의도/입력 버전, 통합 동작을 확인한 뒤 검증 통과로 바꾼다. 보고만 있고 재현 근거가 없으면 미검증으로 남긴다.
- 핵심 구현의 독립 검증은 해당 코드를 작성하지 않은 에이전트가 원자료·명세에서 기대 결과를 도출해 수행한다. 구현자의 설명만으로 통과시키지 않는다. 메인은 독립 지적과 재검사 결과를 확인하고 중요한 발견·해결을 사용자에게 설명한다.
- 에이전트 간 불일치는 출처와 관측으로 판단한다. 통상 구현 판단은 메인이 근거를 남겨 결정하고, 사용자 목적·요구·중요 절충이 바뀌면 QNA로 보낸다.
- 단계와 작업 상태는 근거로 판정한다. 임의의 완료 백분율로 G0~G6의 미완료·답변 대기·실패를 가리지 않는다. 실제 AI 제안의 채택·수정·보류, 결함 재현→수정→재확인, 인간 판단은 WORKLOG의 근거에 연결한다.

## 답변 변경·중단·재개

1. **저장:** 현재 단계, 열린 QNA, 의도 버전, 요구 상태, 코드·입력 버전, 진행 작업/에이전트 ID, 다음 행동과 미검증 변경을 WORKLOG에 남긴다. 작업 기록에 없는 완료를 기억만으로 복원하지 않는다.
2. **확인:** 재개 시 실제 QNA 답변, USER_INTENT, REQUIREMENTS, SPEC의 명세·계획, WORKLOG, CHECKLIST, 현재 파일 차이를 읽는다. 기존 에이전트가 살아 있는지 현재 도구로 확인한다. ID가 기록되어 있다는 이유만으로 실행 중이라 가정하지 않는다.
3. **영향 판정:** 새 답변·원자료·입력 변경을 확인하면 관련 요구→결정→SPEC·계획→작업→검증→HANDOFF와 연결된 체크 항목만 재검토로 바꾼다. 메인이 의도 버전/작업 세대를 갱신하고 영향받는 에이전트에 알린다.
4. **낡은 쓰기 중지:** 영향받는 작업을 취소·중단하거나 반환을 보류시킨다. 가능한 도구로 중단 상태를 확인한 후 수정 소유권을 다시 배정한다. 확인할 수 없으면 같은 경로에 새 쓰기를 시작하지 않는다. 에이전트는 버전 불일치나 취소를 알게 되면 쓰기를 멈추고 현재 변경과 미완료를 반환한다.
5. **늦은 결과 격리:** 이전 세대의 보고·코드가 도착하면 자동 통합하지 않는다. 기존 파일 차이를 보존·검토하고 유효한 변경만 현재 요구로 다시 검증한다. 사용자의 기존 변경을 덮어쓰거나 임의 삭제하지 않는다.
6. **재개:** 유효한 선행 조건과 소유권을 확인한 작업부터 다시 배정한다. 이미 유효한 답변을 재승인받지 않는다. 시간 부족이나 사용할 수 없는 감사 기능은 남은 제약으로 유지하고, 종료 시 미완료 범위와 재개에 필요한 조건을 명시한다.
