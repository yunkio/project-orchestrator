메인만 편집한다. 상세 결과는 실제 산출물·고유 보고서로 연결한다. 상태는 근거로 갱신하며 완료 백분율로 대신하지 않는다.

## 문서 매핑

기존 문서가 같은 역할이면 실제 경로를 연결한다. QNA와 의도 기록은 서로 분리한다.

| 역할 | 실제 경로 |
|---|---|
| QNA — 사용자 선택·답변 | |
| USER_INTENT — 원문 답변과 목적·해석 | |
| REQUIREMENTS — 원자료와 요구 추적 | |
| SPEC — 구현 기준 명세와 실행 계획 | |
| WORKLOG — 단계·배정·증거·재개 | |
| CHECKLIST — 단계·지시·요구 이행과 지속 확인 | |

## 제품의 실행 흐름

요청→계산→진행 상태→검증→저장/조회에 실제 구성요소·데이터/상태 전이를 연결한다. 실패·시간 제한·데이터 버전 분기도 해당 위치에 적는다. 작업 배정 그래프와 섞지 않는다.

## 작업 DAG와 배정

SPEC의 계획 작업 ID를 사용해 선행·병렬·통합 관계를 그래프로 표시하고 아래 표에 실제 상태를 유지한다. 상태: 대기 / 진행 / 답변 대기 / 반환 / 검증 통과 / 취소 / 미완료. `반환`은 메인의 통합 검증 전 상태다. 소유 경로는 겹치지 않게 정한다.

| 작업 ID·목적 | 명세·요구·의도·체크 ID / 버전·세대 | 선행·입출력 계약 | 소유자·에이전트 ID / 수정 경로 | 자원·중단 조건 | 완료 검사·반환 근거 | 상태 |
|---|---|---|---|---|---|---|

## 결정·AI 협업·실행 근거

중요한 사용자 선택은 QNA로 연결한다. 일상 작업을 모두 기록하지 말고 결과와 이해에 영향을 주는 판단·결함·검사만 남긴다. 사람의 직접 확인과 AI 관측을 구분한다.
