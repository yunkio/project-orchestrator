# 프로젝트 이행 체크리스트

> 메인이 실제 원자료와 기록을 읽고 갱신한다. 처음에는 전부 대기다. 상태와 근거를 함께 채우며, 양식 생성·계획·에이전트 반환만으로 확인 완료를 표시하지 않는다. 채운 문서는 원문 감사 1차와 그래프 첫 읽기에 전달하지 않는다.

- 현재 요청·허용 범위 / 범위 밖의 단계와 근거:
- 의도·SPEC·코드·입력 버전 / 최근 확인 시점:
- 실제 문서 위치: QNA / USER_INTENT / REQUIREMENTS / SPEC / WORKLOG / HANDOFF:

상태: 대기 / 진행 / 답변 대기 / 확인 완료 / 재검토 / 미완료 / 적용 없음. 적용 없음에는 출처·이유, 답변 대기에는 QNA와 의존 작업을 연결한다. 근거에는 해당 파일·항목·실행과 대상 버전을 적는다.

## 프로젝트 지시와 요구 연결

실제 자료를 읽은 뒤 행을 만든다. C-I는 프로젝트 지침·산출물·도구/시간 등의 실행 조건, C-R은 REQUIREMENTS의 조건별 요구에 연결한다. 모든 필수 요구가 빠짐없이 연결됐는지 역방향 대조한다. 상세 조건·로그를 복사하지 않는다. 단계 통과와 요구의 최종 이행을 구분한다. 예를 들어 G2 명세 반영·검사 준비는 현재 단계 확인에 적고, 아직 구현·검증하지 않은 제품 요구는 최종 완료로 표시하지 않는다. 이후 단계의 미완료만으로 준비된 현재 단계 작업을 막지 않는다.

| 체크 ID | 종류·적용 단계 | 원문 지시 위치 또는 요구 ID·통과 조건 위치 | 연결 SPEC·작업 | 현재 단계 확인 | 최종 이행 상태 | 최신 근거·대상 버전 / 다음 행동 |
|---|---|---|---|---|---|---|

## 최근 확인과 재검토 이력

시작·재개, 단계 진입/종료, 위임, 주요 쓰기·반환·통합, 답변/자료/명세 변경, 결함 수정, 최종 전달 전에 관련 항목을 실제 확인한 뒤 기록한다. 도구 호출마다 전 항목을 반복하지 않는다. 이전 근거와 이력을 지우지 않고 영향받은 항목만 재검토한다.

| 시점·확인 주체 | 계기·확인한 항목 ID | 의도·SPEC·코드·입력 버전 | 확인 결과·상태 변경 이유 | 남은 문제·QNA·다음 행동 |
|---|---|---|---|---|
