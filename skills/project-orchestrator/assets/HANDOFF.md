[누구의 어떤 업무 문제를 해결하는지, 기존 방식의 어려움과 성공 기준을 연결해 설명한다. 실제 작동하는 핵심 경로와 미완료·목업 범위를 분명히 적는다. 사용자 목적은 USER_INTENT와 실제 답변에 연결한다.]

### 선택과 절충

[가장 중요한 방법을 왜 선택했는지 실제 대안과 비교해 몇 문장으로 설명한다. 얻은 점, 포기한 점, 성립 가정을 연결한다. 사용자 직접 결정과 에이전트의 위임된 판단을 구분하고 결정 기록을 연결한다.]

| 단계 | 전달 데이터·상태·버전 | 실제 코드 위치 |
|---|---|---|
| [실제 단계] | [주요 값, 단위, 상태 소유자] | [파일/함수 링크] |

### 확인한 결과와 그 한계

[어떤 입력과 실행으로 무엇을 확인했는지 설명한다. 유효성, 관측된 품질, 최적성·정확성 증명 여부를 구분한다. 작은 사례 또는 제한 시간의 결과를 전체 입력의 보장으로 확대하지 않는다. 실제 수치와 근거를 연결한다.]

### 실패·변경과 남은 일

[시간·크기 제한, 오류, 빈 결과, 취소·늦은 응답, 원본 변경 중 실제 가능한 경우에 무엇이 일어나고 사용자에게 어떻게 보이는지 설명한다. 알려진 한계와 다음에 할 가장 가치 있는 확인을 적는다.]

## 설계 검토와 유지보수

### 1. 선택 — 왜 이 문제와 방법인가?

**핵심 설명:** [목표·제약과 채택 방법을 연결한 핵심 설명]

**원리와 절충:** [실제 대안, 선택 기준, 얻은 점과 포기한 점, 적용 가정]

**판단 주체:** [사용자 직접 답변/QNA 링크 또는 에이전트 결정/WORKLOG 링크]

**코드·실행 근거:** [관련 요구, 구현 위치, 실제 비교·검사 기록]

**조건을 바꾸면:** [중요한 제약 하나가 바뀔 때 선택이 유지되는지와 이유]

**이해 확인 → QNA:** [자기 말로 선택 이유와 대안이 유리한 조건을 설명할 질문·ID]

### 2. 흐름 — 입력은 어떻게 결과가 되는가?

**핵심 설명:** [실제 사용자 요청 하나의 전체 경로]

**원리와 상태:** [원본·변환·입출력 계약·상태 소유자·저장 위치·조회 연결]

**코드·실행 근거:** [흐름 노드별 구현 위치, 전체 경로를 실행한 명령/화면 동작·기록]

**조건을 바꾸면:** [입력 형식·요청 순서 등 실제 중요한 변화의 처리]

**이해 확인 → QNA:** [특정 값이 어디서 만들어지고 어디서 확인되는지 추적할 질문·ID]

### 3. 검증 — 결과를 왜 믿을 수 있는가?

**핵심 설명:** [권위 있는 원본과 규칙에서 결과를 확인하는 방법]

**신뢰 경계:** [생성기의 어떤 값을 믿지 않고 무엇을 별도로 재계산하는지]

**코드·실행 근거:** [검증기 또는 독립 기대 결과의 위치, 정상·위반 후보와 실제 판정]

**주장의 범위:** [유효성이 확인된 조건, 별도 품질·최적성 근거가 필요한 부분]

**조건을 바꾸면:** [조작된 합계·미등록 ID·중복·제약 위반 등 해당 사례의 실제 처리]

**이해 확인 → QNA:** [잘못된 출력 하나를 구성하고 거부 이유를 설명할 질문·ID]

### 4. 실패 — 시간이 부족하거나 데이터가 바뀌면?

**핵심 설명:** [실제 한도와 실패·변경 정책]

**동작과 화면:** [중단·오류·빈 결과·부분 결과·오래된 데이터 중 적용되는 상태와 사용자 표시]

**코드·실행 근거:** [한도 집행·현재 요청/버전 확인 위치, 지연·변경·오류 주입 결과]

**조건을 바꾸면:** [계산 중 원본 변경 또는 늦은 응답이 왔을 때의 결과]

**이해 확인 → QNA:** [성공으로 표시하면 안 되는 상황과 실제 처리 이유를 설명할 질문·ID]

### 5. 품질 — 얼마나 좋으며 무엇까지 보장하는가?

**핵심 설명:** [실제 관측한 품질과 비용, 보장할 수 없는 범위]

| 근거 종류 | 실제 결과 또는 미적용 이유 | 범위·제한 |
|---|---|---|
| 기준 방법 비교 | [동일 입력·제약·예산에서의 관측값과 링크] | [비교 조건] |
| 기대 결과를 검산할 수 있는 작은 사례 | [검산/완전 탐색 결과와 링크] | [해당 사례의 범위] |
| 조건 변화 | [규모·용량·가중치 등의 변화와 결과] | [관측 범위] |
| 최적성·정확성 증명 | [근거와 가정 또는 증명 없음] | [모델·입력·코드·종료 상태 중 입증한 범위] |

**코드·실행 근거:** [목적함수/품질 기준·종료 조건 위치, 실제 실행 기록]

**조건을 바꾸면:** [주요 조건의 변화가 결과·시간·실패에 미치는 영향과 미확인 부분]

**이해 확인 → QNA:** [유효한 결과와 좋은 결과·최적 결과의 차이를 실제 사례로 설명할 질문·ID]

### 6. AI 협업 — 어떤 제안을 판단하고 무엇을 바꿨는가?

**핵심 설명:** [실제 협업에서 중요한 판단과 결과]

| 실제 제안·출처 | 판단 주체와 수용/수정/기각/보류 이유 | 실제 변경 | 전후 명령·결과 또는 증거 부족 |
|---|---|---|---|

**조건을 바꾸면:** [AI 제안이 요구·원본·실행 결과와 충돌할 때 판단할 근거]

## 스스로 확인하고 이어가기

후속 작업에 필요한 핵심 선택·전체 흐름·검증 범위를 설명할 수 있는지 확인한다. 조건 하나를 바꾸기 전에 결과를 예측한 뒤 실제 동작과 비교하고, 잘못된 출력이 어디서 거부되는지 확인한다. 사용자 답변은 대신 작성하지 않고 QNA의 사용자 답변란에서 받는다.

| QNA 질문 | 연결 항목·근거 | 실제 답변에서 확인한 내용 | 남은 오해·다음 행동 |
|---|---|---|---|
| [질문 ID·링크] | [항목·코드·근거] | [실제 답변 링크 또는 답변 대기] | [필요한 후속 질문/없음] |

**알려진 한계·미완료:** [필수 요구 누락, 검사 실패, 미실행, 가정의 영향]
