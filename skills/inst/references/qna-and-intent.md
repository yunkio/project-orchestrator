# 질문과 의도 이해

질문과 실제 답변은 QNA에, 작업 내내 적용할 목적은 별도 USER_INTENT에 저장한다. 메인이 기록을 관리하고 사용자는 답변 칸을 편집한다.

## 필요한 질문 만들기

현재 결정에 필요한 질문만 묶어 작성한다. 사실·경로 확인은 짧게 묻고, 선택에는 대안·이점·비용·추천 이유를 붙인다. 질문에는 다음을 둔다.

- 질문 ID·버전, 답할 대상과 실제 채널, 질문이 필요한 이유.
- 원자료나 기존 답변의 관련 조건, 결정할 차이, 답을 기다리는 작업.
- 선택지·trade-off와 비워 둔 답변 칸. 직접 제안과 보류도 허용한다.

현업 질문은 현재 업무의 병목·성공/실패 사례·필수 조건에 집중한다. 허용된 채널에서는 질문과 응답 원문·출처를 기록하고, 사용자가 전달해야 하는 경우에는 보낼 질문과 받은 답변 칸을 마련한다. 응답이 없는 항목은 대기로 둔다.

## 답변을 해석한 뒤 반영하기

1. 수정 알림을 받으면 디스크의 실제 QNA를 읽고 바뀐 답변과 질문 문맥을 확인한다. 변경 범위를 확실히 비교할 수 있으면 관련 질문을, 범위가 불분명하면 전체를 읽는다. 쓰기 직전에도 사용자 편집을 확인한다.
2. 당시 질문·조건·선택지와 답변·직접 밝힌 이유를 접수 기록에 보존한다. 사용자가 답변 칸을 나중에 편집해도 접수 당시 원문을 찾을 수 있도록 별도 인용으로 남긴다. 채팅으로 받은 명확한 답도 출처와 함께 원문으로 옮긴다. 선택 번호는 당시 선택지로 해석한다.
3. 먼저 **어떤 문제를 피하거나 어떤 결과를 얻으려는 답인지** 판단한다. 사용자 명시 내용, 직접 말한 이유, AI가 해석한 목적, 남은 불확실성을 구분한다.
4. 해석이 실제 결과를 달리 만들 정도로 불분명하면 좁은 후속 질문으로 확인한다. 이유가 없어도 의미가 명확한 답은 적용하고, 알 수 없는 숨은 동기를 지어내지 않는다. 빈칸·추천 표시·침묵은 답변으로 취급하지 않는다.
5. USER_INTENT의 현재 목적·성공 기준·우선순위·제약·위임 범위를 갱신하고, 답변 ID와 명세·작업에 미치는 영향을 연결한다. 해당 의도를 반영한 다음 행동을 사용자에게 설명한다.

답이 충분히 명확하면 다시 승인받는 단계를 추가하지 않는다. 이미 답한 조건을 참조하고, 의미가 달라진 질문은 새 버전으로 남긴다. 현재 기준은 상단에, 과거 답변의 문맥은 아래 접수 이력에 보존한다.

## 충돌과 작업 복귀

원자료·현업 발언·사용자 선택이 충돌하면 양쪽 출처와 결과 차이를 보여 준다. 명시된 우선순위나 권한 있는 답변으로 해결한다. 대기하는 것은 해당 답에 의존하는 작업이며, 독립 작업은 계속한다.

문제가 풀리면 의도 → SPEC의 관련 요구·설계 → CHECKLIST의 다음 행동을 갱신한다. 사용자에게 이번 답을 어떻게 이해했고 어떤 작업을 이어갈지 알린 뒤 본래 흐름으로 돌아간다.

## 경로와 기록 준비

기록 경로가 있으면 기존 문서부터 읽는다. 위치가 미정이면 알려진 쓰기 가능한 현재 폴더 아래 임시 QNA에 빠진 경로를 묻고 실제 링크를 전달한다. 확정된 경로에서는 필요한 양식만 보완하며 사용자가 쓴 답변·메모를 보존한다. 경로조차 알 수 없거나 쓰기가 불가능하면 필요한 위치를 설명한다. 파일 편집 후 짧은 채팅 알림을 받아 재개하며, 파일 감시 기능이 없는 환경에서 자동 재개를 약속하지 않는다.
