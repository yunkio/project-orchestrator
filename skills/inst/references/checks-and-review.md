# 요구 확인과 작업 복귀

SPEC은 원자료·요구·명세의 기준이며 CHECKLIST는 현재 목적·단계·배정·다음 행동과 확인 근거의 기준이다. 동일한 상태를 여러 문서에서 관리하지 않는다.

## 원자료에서 요구로

범위 안의 명세·README·예제·데이터 설명·부록·현업 대화를 실제로 읽고 자료별 위치·기준 버전·읽은 범위·미독 영향을 SPEC에 기록한다. 각 요구를 출처·역할/상황·기대 결과·금지 결과·관측 가능한 통과 조건으로 나눈다. 원문 조건, 사용자 선택, 현업 제안, AI 가정을 구분한다.

명시된 우선순위나 확인된 답으로 충돌을 해결한다. 중요한 미독·불확실성은 QNA와 의존 작업으로 연결한다. 요구별로 구현 작업·코드·검사 근거와 상태를 SPEC에서 관리한다. 프로젝트 지침·산출물·도구와 시간 제약도 실제 출처에 연결한다.

## 체크리스트 사용

체크리스트 상단에는 다음을 유지한다.

- 본래 목적·성공 기준·현재 요청 범위와 실제 문서 위치.
- 현재 단계·진행할 항목·관련 요구 ID·다음 행동.
- 대기 질문·미해결 문제·현재 의도/명세·코드/입력 기준.

절차 항목은 `대기 / 진행 / 답변 대기 / 확인 완료 / 재검토 / 미완료 / 적용 없음`으로 관리한다. 확인 완료에는 실제 근거, 적용 없음에는 원문이나 요청 범위에 따른 이유가 필요하다. 미구현·미실행·도구 부족은 미완료로 남긴다. 요구의 최종 충족은 SPEC의 통과 조건으로 판정하며, 준비된 명세를 구현하기 위해 이후 검사의 완료를 기다릴 필요는 없다.

시작·재개, 사용자 기준 변경, 위임 조건 변경, 통합 결과 판정, 최종 전달 때 관련 항목을 확인한다. 같은 작업에 겹친 계기는 한 번의 확인으로 묶고, 상태·판단·근거가 달라진 내용만 기록한다. 모든 필수 요구와 지시가 SPEC에 있고 계획·검사로 연결됐는지 대조한다.

문제가 생기면 **현재 항목의 목적과 통과 조건 → 원인·영향 → 필요한 QNA → 확인한 의도 → 기준 갱신 → 다음 행동**을 따라간다. CHECKLIST의 복귀 기록에는 문제, 판단·답변 근거, 영향 항목, 이어갈 작업을 남긴다. 중요한 목적·명세 변경은 변경 전후 기준과 출처를 이 기록에 보존하고, 문서 상단에는 현재 기준을 유지한다. 문제를 해결하기 위한 부수 작업은 합의된 목적과 범위에 연결한다.

## 독립 원문 우선 검토

구현 전에는 요구·명세·계획을, 최종 통합 후에는 실제 결과를 독립 검토한다. [에이전트 절차](execution.md)의 새 맥락 조건을 적용한다.

1. 검토자에게 원 사용자 요청·원자료 경로·적용 제약과 **답변 당시 질문·조건·선택지·실제 답변·직접 밝힌 이유**를 제공한다. 부모가 채운 SPEC·CHECKLIST·의도 해석·예상 결함은 이 단계에 제공하지 않는다.
2. 검토자는 원자료에서 요구·충돌·불확실성과 판정 조건을 도출해 고유한 첫 보고를 반환한다. 메인은 보고를 보존한 뒤 다음 자료를 공개한다. 같은 파일의 첫 판단을 나중 결론으로 덮어쓰지 않는다.
3. 현재 의도·SPEC·CHECKLIST·해당 단계의 코드·실행 근거를 공개해 독립 목록과 대조한다. 지적에는 출처, 기대 조건, 실제 차이, 영향과 확인 방법을 둔다.
4. 메인이 지적을 확인해 수정·근거 있는 기각·미해결로 처리한다. 수정 후 관련 검사와 설명을 재확인하고 다음 행동을 정한다.

첫 보고와 후속 대조의 순서를 고유 보고서와 반환 기록으로 남기면 된다. 프로젝트가 변조 방지 증거를 요구할 때 해시·커밋 등을 추가한다.

## 판정과 종료

중요한 미확정 답이나 선행 조건 미충족은 해당 작업을 보류시킨다. 요구가 바뀌면 연결된 결정·계획·구현·검사·그래프만 재검토한다. 이전 근거는 이력으로 보존하고 현재 기준에서 필요한 확인을 수행한다.

최종 전달 전에는 사용자 요청 범위의 필수 요구, 역할별 전체 흐름, 독립 지적 처리, 최신 검사, 그래프와 설명의 실제 일치를 확인한다. 사용할 수 없는 검증은 영향과 재개 조건을 적어 인계한다. 스스로 수행한 보완 검사는 독립 검토와 구분한다.
